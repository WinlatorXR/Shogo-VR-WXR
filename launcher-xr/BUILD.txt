Building ShogoVR.exe, the minimal WinlatorXR container launcher (MSVC).

  1. Open an x86 Developer prompt, or in a script use:
       cmd /c ""<VS>\Common7\Tools\VsDevCmd.bat" -arch=x86 && ..."
     where <VS> is your Visual Studio 2022+ Build Tools installation.

  2. Compile the resources and the source:
       rc.exe /nologo /fo ShogoVR.res ShogoVR.rc
       cl.exe /nologo /O2 /MT /EHsc /W3 /DUNICODE /D_UNICODE /c ShogoVR.cpp
       link.exe /nologo /SUBSYSTEM:WINDOWS /OUT:ShogoVR.exe ShogoVR.obj ShogoVR.res

  ShogoVR.exe is a windowless EXE (not a .bat, not a shortcut).  It finds
  Client.exe next to itself, or one/two folders up (so it also works from the
  overlaid ShogoVR folder next to Client.exe), launches the game with the same
  -rez list the GUI launcher builds (base game, Custom, map packs, single
  player, then ShogoVR last so its CShell.dll wins), waits for it to exit and
  returns its exit code.

  Deploy: copy ShogoVR.exe alongside Client.exe in the WinlatorXR container
  and start it from there.  Its icon comes from assets/shogo.ico (the icon of
  Shogo.exe).

  Auto-update:  before launching, ShogoVR.exe reads the release channel
  (see Docs/PROJECT_PLAN.md section 7) - version.txt and notes.txt from
  https://raw.githubusercontent.com/WinlatorXR/Shogo-VR-WXR/refs/heads/main/AutoUpdate/
  - and compares the version with the version.txt sitting next to the EXE.
  If they differ (or the local file is missing) it shows a YES/NO box:

    A new update is available, download now?
    Version <version>: <notes>

  YES downloads version.txt and
  https://github.com/WinlatorXR/Shogo-VR-WXR/raw/refs/heads/main/AutoUpdate/CShell.dll
  into a ShogoVRUpdate folder next to the EXE, then - only once both downloads
  are complete - copies version.txt next to the EXE and CShell.dll into the
  ShogoVR folder next to Client.exe, and empties ShogoVRUpdate (keeping the
  folder).  NO, no internet, or any download/copy failure just launches the game
  with what is already installed (a failed CShell.dll copy restores the old
  version.txt so the update is offered again next time).  What happened lands in
  ShogoVR_update.log next to the EXE.

  The updater links winhttp.lib; the source carries
  #pragma comment(lib, "winhttp.lib"), so the link lines above need no change.

  Release step:  put the new CShell.dll in AutoUpdate/, bump
  AutoUpdate/version.txt AND launcher-xr/version.txt to the same number, and
  rewrite AutoUpdate/notes.txt.
